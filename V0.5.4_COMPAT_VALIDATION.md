# v0.5.4 compatibility validation — DSH `0.2.2-rc.1` and the `<0.2.2` range

Date: 2026-11-06. Branch: `compat/dsh-0.2.2-rc.1`. Base: `main` at
`d46beea` (v0.5.3 release record).

## Result

`0.5.4` installs through the native DSH plugin manager without any version
exemption and passes the eight real-assembly end-to-end probes on both
**DSH `0.2.1-rc.3`** (new minimum) and **DSH `0.2.2-rc.1`**. The released
`0.5.3` is refused by `0.2.2-rc.1`. No plugin source changed.

## Why 0.5.3 does not run on 0.2.2-rc.1

DSH (`@deepseek-ai/dsh-app-boot`) decides plugin admission from an own
`engines.dsh` alone, using `semver.satisfies(runtime, range, { includePrerelease: true })`.
`0.2.2-rc.1` does not satisfy `>=0.2.1-rc.2 <0.2.2-0`. Measured on an isolated
`@deepseek-ai/dsh@0.2.2-rc.1` host:

> `dsh: installation rejected: Plugin dsh-mail-notify@0.5.3 is incompatible with dsh 0.2.2-rc.1: requirements {"engines.dsh":">=0.2.1-rc.2 <0.2.2-0"}`

The installation was rolled back by DSH. No `allow-version` exemption was used.

## Range decision

Declared in `engines.dsh` and both shared-instance peers: `>=0.2.1-rc.3 <0.2.2`.

| Host | DSH gate (`includePrerelease`) | npm default semantics |
| --- | --- | --- |
| `0.2.1-rc.2` | reject | reject |
| `0.2.1-rc.3` | **admit (measured)** | admit |
| `0.2.1-rc.5`, `0.2.1` | admit (untested) | admit |
| `0.2.2-alpha.3` | admit (untested) | reject |
| `0.2.2-rc.1` | **admit (measured)** | reject |
| `0.2.2-rc.9` (hypothetical) | admit (untested) | reject |
| `0.2.2` | reject | reject |
| `0.2.3-rc.1` | reject | reject |

Evaluated with semver `7.8.6`, the version the `0.2.2-rc.1` host ships. The
DSH gate is authoritative for admission. The npm-default column applies only to
peer checks by package managers. In a DSH profile the host provides these
packages, and pnpm prints the same non-blocking "Issues with peer dependencies"
warning on both measured hosts, `0.2.1-rc.3` included.

## API changes `0.2.1-rc.3` → `0.2.2-rc.1` and their effect

Package tarballs for every host package the plugin imports were compared.
`dsh-credentials` and `dsh-client-ui-slots` are unchanged apart from the
version string. The others changed, and none breaks a surface the plugin uses:

| Change | Effect on the plugin |
| --- | --- |
| `dsh-session`: ordinary forks no longer set `parentSession`; subagent classification is by `origin` | None. `src/runtime-adapter.ts` already classifies by `origin`/`delegationDepth` and ignores `parentSession`. |
| `dsh-session`: new `turn/end` failure code `TOOL_ACTIVATION_FAILED` | None. Failure codes pass through verbatim (`src/completion.ts`); the mail shows the new code. |
| `dsh-session`: store-owned sessions are read-only until `session/created` completes | None. The plugin only observes events and never appends. |
| `dsh-user-questions`: new caller-declared `intent.kind: 'approval'` question | No shipped `0.2.2-rc.1` package produces it. If a third-party caller does, the plugin mails it as "Input required", not "Approval required". |
| `dsh-user-approval`: projection-based internal state | None. `approval/asked` / `approval/decided` are still emitted with the same types. |
| `ask_user_question` tool | Name and `multi_select` argument unchanged. |
| Client packages (`dsh-client-*`, `dsh-api-*`) | All three TypeScript programs compile; `plugins.bundle.config` slot still exists. |

## Hosts and isolation

- `0.2.2-rc.1`: npm `@deepseek-ai/dsh@0.2.2-rc.1` (cordis `4.1.0`, schemastery
  `3.19.0`), installed into a disposable session scratch directory.
- `0.2.1-rc.3`: the existing isolated install
  `E:\Projects\DSHarness\_phase052-compat\host-rc3`, used read-only as
  `DSH_INSTALL_ROOT`.
- Every run used a fresh disposable `DSH_HOME`. The operator's `~/.dsh`, desktop
  app and running hosts were not touched. Scripted model provider, loopback SMTP,
  synthetic credentials; no real mail and no model quota. No processes were left
  running.

## Not covered

  `dsh web` (covered only by typecheck against the client packages and the unit
  suite's card/controller tests).
- Real SMTP delivery.
- Any admitted host other than `0.2.1-rc.3` and `0.2.2-rc.1`.
